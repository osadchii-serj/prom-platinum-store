# PROM — испытание изменения статуса через API

Статус: **предложено / не испытано на реальном POST**.

## Основание

Скриншоты официального Swagger `POST /products/edit` от 22.10.2026: тело запроса — массив объектов, `id` обязателен, `status` enum `on_display`, `draft`, `deleted`, `not_on_display`. Ответ 200 содержит `processed_ids`, `errors`. `presence`: `available`, `not_available`, `order`.

Реальный GET карточки `3243922294`: `status=on_display`, `presence=not_available`, `sku=PROM-TEST-20261022-001`.

## Границы эксперимента

- Единственный разрешённый ID: `3243922294`.
- Переходы: `on_display → draft` и `draft → on_display`.
- `deleted` и `not_on_display` запрещены в данном скрипте.
- По умолчанию только предпросмотр. POST требует `--отправить` и точную фразу.
- Отправляем только `[{"id":3243922294,"status":"draft"}]` (либо `on_display`).
- Сверяем `processed_ids`, `errors`, затем GET. Если HTTP/GET не подтвердил результат — повторять POST автоматически запрещено.
- При отказе API или сетевой неопределённости сначала отдельный GET, затем решение оператора.

## Команды

```bash
uv run python scripts/исследование/изменить_статус_тестовой_карточки.py --статус draft
uv run ruff check src tests scripts
uv run mypy src
uv run pytest -q
```

После проверки предпросмотра и явного решения оператора:

```bash
uv run python scripts/исследование/изменить_статус_тестовой_карточки.py --статус draft --отправить
```

Для возврата из `draft` в `on_display` используйте `--статус on_display` (сначала предпросмотр). **Восстановление публикации — отдельная подтверждаемая операция, не автоматическая.**

## Критерий приёмки

POST обрабатывает ровно один ID без ошибок; следующий GET показывает целевой `status`; SKU и ID совпадают. Поведение сайта проверяется отдельно в кабинете.
