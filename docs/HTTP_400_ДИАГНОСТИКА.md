# Диагностика HTTP 400 — этап без сетевых запросов

Патч заменяет **три** файла `src/prom/api/операции_импорта.py`, `src/prom/api/результаты_импорта.py`, `src/prom/сценарии/управление_импортом.py` и добавляет тест `tests/test_диагностика_http_импорта.py`.

Перед распаковкой сохранить Git-коммит или копии файлов. Распаковать с сохранением структуры в корень проекта. Не удалять журналы `loadtest_500_001`, `002`, `003` и не отправлять POST.

Проверки:

```bash
uv run ruff check .
uv run mypy src
uv run pytest -q
```

Новый журнал будущего запроса содержит `статус_http` и `код_ошибки` (только короткий машинный код из JSON-полей `code` или `error_code`). Свободные тексты ошибок, тело ответа, токены и персональные данные не записываются. Если сервер возвращает только текстовое описание или поле `message`, диагностический код будет `None`; причина HTTP 400 останется неизвестной. Старые журналы читаются с `None` в новых полях.

Патч не меняет параметры, адреса, содержимое или частоту POST, не разблокирует неопределённые попытки. Новые POST требуют отдельного согласования.

Внимание: файлы сформированы на основании ранее предоставленных версий модулей; перед применением сравнить изменения с текущими версиями в Git. Проверки проекта должен выполнить пользователь.
