# PROM — решения, предложения и открытые вопросы

Дата: 2026-10-20.

## Согласовано
- Приоритет: полная инвентаризация магазина и API → испытание одной карточки → проверенная массовая загрузка около 1000 карточек → разработка бизнес-алгоритмов после обсуждения с владельцем.
- Сохранять исследовательские результаты и предложения для последующего возвращения.
- Не проводить реальные операции записи без явного разрешения.
- Технологии и порядок согласований определены в PROM_REGULATIONS.md.

## Предложено, НЕ утверждено
- Внутренний реестр соответствий: источник/поставщик + исходный ID + запись в нашей системе + Prom `id` + `external_id` + `sku` + связи разновидностей + статус проверки.
- Запрет автоматического сопоставления только по `sku`; дополнительные проверки при конфликте.
- Раздельное управление полями поставщика и подготовленными магазином описаниями, SEO и категориями.
- Комбинированный подход: файловый импорт для больших партий, адресные API-операции для разрешённых точечных изменений.
- Предварительный просмотр, подтверждение, аудит, сверка, повтор и восстановление для всех массовых операций.

## Отложено до обсуждения с владельцем
- Одна карточка на товар с несколькими поставщиками или отдельные карточки.
- Выбор основного поставщика, алгоритмы цен, запасов, скидок, заказов, продаж и SEO.
- Автоматическое устранение кандидатов на дубли.

## Неизвестно / требует испытаний
- Полный API-контракт создания и удаления карточки.
- Соответствие `offer id`, идентификатора Excel и `external_id`.
- Семантика пустых полей, повторного импорта и частичных ошибок.
- Реальное поведение восстановления удалённой карточки (возможно, полного восстановления нет).
