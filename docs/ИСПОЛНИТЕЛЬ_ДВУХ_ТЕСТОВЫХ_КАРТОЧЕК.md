# PROM — исполнитель этапов двух тестовых карточек

**Статус:** реализовано локально; реальный POST не проверен.

Использует сохранённый `data/групповые_операции/план_двух_карточек.json`, созданный предыдущим предпросмотром. Не создаёт новый снимок и не изменяет его. Разрешены только ID 3243922294 и 3244158641 с закреплёнными SKU. План сравнивается с заново вычисленным планом, чтобы исключить подмену этапов.

Команда без `--отправить` выполняет только GET и показывает **следующий** этап:

```bash
uv run python scripts/испытать_групповые_статусы.py
```

После успешного Fedora Gate и **отдельного согласования реального испытания** команда `--отправить` разрешает только один этап, с интерактивной фразой подтверждения:

```bash
uv run python scripts/испытать_групповые_статусы.py --отправить
```

Запуск повторяют для каждого этапа только после просмотра результата предыдущего. **Не запускать с `--отправить` до отдельного разрешения.**

## Защита

- Перед POST проверяются ID/SKU/status через GET.
- Перед отправкой записывается намерение в `план_двух_карточек.журнал.jsonl` с `fsync`.
- Ответ POST должен содержать ровно все ожидаемые ID в `processed_ids` без `errors`.
- После POST проводится GET-сверка. Для `deleted` ожидается 404; это правило применяется только к подтверждённому этапу.
- В журнал записывается подтверждение только после сверки.
- При тайм-ауте, ошибке или остановке между записями журнал блокирует следующий запуск. **Автоматического повтора и автоматического отката нет.** Требуется ручная сверка и отдельная процедура восстановления.
- Межпроцессная блокировка `flock` рассчитана на Fedora/Linux.

## Ограничения

Переход `draft → on_display` после реального восстановления удалённого товара ещё не проверен. Успешный GET не доказывает восстановление поисковой индексации, рекламных параметров или всех свойств карточки. Отдельная полная сверка кабинета остаётся обязательной. Программа не рассчитана на реальные товары или на произвольное число карточек.
