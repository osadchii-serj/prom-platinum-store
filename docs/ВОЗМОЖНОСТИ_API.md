# PROM — возможности API и жизненный цикл карточки

Статус: **исследование**. Не считать предположения подтверждёнными контрактами.

## Подтверждено реальным испытанием 22.10.2026

- Импорт одной позиции через `POST /products/import_file` привёл к созданию карточки в кабинете Prom.ua.
- Артикул: `PROM-TEST-20261022-001`; ID: `3243922294`.
- После импорта количество объектов, получаемых проверкой каталога через API, изменилось с 679 на 680.
- Кабинет показал «Опубліковано» и «Немає в наявності».
- Предупреждения импорта о переводе и идентификаторах не помешали созданию.
- Прежний диагностический HTTP 400 и успешный результат импорта требуют отдельной сверки по времени и конкретному запросу; причинно-следственная связь не доказана.

## Требует исследования

| Вопрос | Статус | Проверка |
|---|---|---|
| Поля GET карточки для публикации | Не проверено | GET одной карточки |
| Создание именно черновика через импорт | Не проверено | Официальная схема + отдельное согласованное испытание |
| Возможность переключать статус через API | Не проверено | Схема `products/edit` и допустимые поля |
| Соответствие «Опубліковано» и «В каталозі» | Не проверено | Сопоставление кабинета и GET |
| Допустимые статусы наличия | Не проверено | Схема и GET |
| Идентификаторы `id`, `external_id`, `sku` | Частично проверено | GET и документация |

## Правила исследования

1. Начинать с GET, не менять карточку и не отправлять повторный POST.
2. Записывать точные ключи JSON, типы и значения; не переводить имена API.
3. Разделять подтверждение документацией, проверку на API и принятие в архитектуру.
4. Для изменения статуса необходимы предпросмотр, согласование и последующая GET-сверка.
5. Не сохранять токены, персональные данные и полный ответ API в репозиторий.
