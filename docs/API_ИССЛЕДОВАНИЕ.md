# PROM — реестр изучения API (начальная версия)

Дата: 2026-10-20. Основа: скриншоты официального Swagger и справки Prom.ua, а также пользовательские результаты реальных GET-запросов. Перед разработкой повторно проверить актуальную документацию и права токена.

| Метод | Назначение | Статус |
|---|---|---|
| GET /products/list | Список товаров, limit, last_id и фильтры по изменению | Проверено чтением; 676 записей |
| GET /products/{id} | Одна карточка по внутреннему id | Проверено чтением |
| GET /products/by_external_id/{id} | Чтение по внешнему идентификатору | Документировано, не испытано |
| POST /products/edit | Редактирование по внутренним id | Документировано, не испытано |
| POST /products/edit_by_external_id | Редактирование по внешним id | Документировано, не испытано |
| POST /products/import_file | Импорт XLS/CSV/XLSX/XML, multipart file + data | Документировано, не испытано |
| POST /products/import_url | Импорт по URL с настройками | Документировано, не испытано |
| GET /products/import/status/{id} | Статус и счётчики задания импорта | Документировано, не испытано |

Это **не полный перечень API**. Для цели пользователя требуется инвентаризация всех разделов Swagger, включая товары, группы, характеристики, заказы, клиенты, сообщения и иные реально представленные разделы — без предположений об их наличии или доступности.

## Зафиксированные особенности
- Для списка товаров Swagger показывает `limit`, `last_id`, `last_modified_from`, `last_modified_to`, `X-LANGUAGE`; `offset` не подтверждён.
- `last_id` описан как верхняя граница по id; диагностика использовала `min(id)-1` и получила 676 уникальных записей.
- В ответах присутствуют `id`, `external_id`, `sku`, `is_variation`, `variation_base_id`, `variation_group_id` и другие поля.
- Для файлового импорта первичный ответ `status=success` не доказывает завершение обработки.
- Статус задания описывает `SUCCESS`, `PARTIAL`, `FATAL`; счётчики `total`, `imported`, `created`, `updated`, `actualized`, `not_changed`, `not_in_file`, `created_active`, `created_hidden`, `with_errors_count`; ошибки по этапам `download`, `store_file`, `validation`, `import`, `download_images`.
- В Swagger замечено расхождение: id задания при запуске показан как string, при запросе статуса как integer/int64.
- Схема содержимого `data` для import_file не выяснена.
- Справка YML: обязательный `offer id` используется для последующих обновлений; соответствие API `external_id` остаётся гипотезой.
- Веб-интерфейс импорта позволяет выбрать поля, режимы принудительного/только существующего обновления, обработку отсутствующих позиций. Применимость этих настроек к API `import_file` не подтверждена.

## Приоритетные вопросы для дальнейшего исследования
1. Полный перечень разделов и методов API; доступность для текущего токена; типы, схемы, права, лимиты, ошибки.
2. Список всех фактических полей товаров, включая вложенные структуры, их заполненность, изменяемость, обязательность и ограничения.
3. Механизмы создания/удаления/скрытия/восстановления товаров: документированные операции и их ограничения.
4. Группы, категории, характеристики, изображения, разновидности и их API-контракты.
5. Заказы, покупатели и другие сущности: только в объёме официально доступного API и с защитой персональных данных.
6. Контракт `data` импорта, сопоставление идентификаторов, идемпотентность, повторы, частичные сбои.
